# Sentinel / 观衡智序 · Enterprise Demo 开发计划

2026-11-13 · 规划稿  
产品需求基线为《Sentinel V3.5 Product & Demo Rebuild Brief》。仓库 README 把当前实现称为 V4.1，把 V5.0 作为战略路线图。为避免版本口径混淆，暂用 **Sentinel Enterprise Demo** 作为交付名称，发布编号在实施时确定。

## 1. 交付目标

升级现有 Web Demo，让评委、投资人和农业企业负责人在约 90 秒内看懂一件事：云南蓝莓基地收到虫害预警后，Sentinel 如何追溯受影响的 750 kg A 级果订单，权衡三个方案，取得经理授权，自动派发模拟工单，并核验最后的履约准备结果。

第一屏明确 Sentinel 是农业企业经营决策与执行系统。演示围绕 **品质、交付、利润** 展开。主线沿用 LOOK → THINK → ACT → PROVE，页面导航按经营任务组织。系统保留原七阶段的可用能力，详细遥测、风险、处方、角色意见及历史从相应业务页面进入。

**交付分两步。** 先验收一条可运行纵向链路，再完成全站 UI、故障路径、证据导出和双语交付。第一阶段即验证正常与阻断两个结果，避免等到最后才发现审批和执行脱节。

视觉优先做 **深海军蓝经营总览 + 高对比的工作区**，青色表示可操作或选中，金色用于模拟经营价值，风险同时用颜色、图标和文字表达。让“750 kg / 3 天 / 当前动作”在投影中一眼可读。用现有可用田间素材辅助讲清证据来源。全局显示 `SIMULATION MODE`、当前场景和数据时间。英文优先，提供 EN / 中文切换，标题、数字和按钮保持足够空间。桌面以 1920×1080、1440×900 验收，另测 768 和 390 px。手机上将三栏改为分段阅读，方案表与执行时间线可逐项查看。

### Stitch 怎么用

采用 [Google Stitch](https://stitch.google.com/) 做前期高保真方案。Google 官方支持以代码或设计文件作为输入、用 `DESIGN.md` 交换设计规则，并把界面导出至 Antigravity。项目可直接把选中的布局和组件规范落实到现有 React/CSS。Stitch 原型与 Antigravity 导出都是设计输入，现有仓库负责应用状态、规则和交互。

1. 提供脱敏旧界面截图、Sentinel 标志、合成蓝莓案例、页面信息优先级及双语文本长度。首轮用这些素材完成设计探索。
2. 只做三个锚点页面：经营总览、决策室、执行中心。对比「全暗色经营控制台」与「深色外壳 + 更明亮的决策工作区」，先看投影可读性、关键数字和阻断状态是否清楚，再定视觉方向。
3. 同时出关键状态：三方案可行或阻断、审批锁定、执行中、质检失败。定稿后形成 `DESIGN.md`，记录色彩、字号、间距、表格、告警、图谱、时间线、响应式和双语规则。
4. 在现有 React 页面实现，使用真实仿真状态截图验收。Figma 适合需要团队批注或精细交付时选用。若 Stitch 账户或导出不可用，按相同规范在本地实现三页可交互稿。

官方资料：[Google Stitch 实时设计与 Antigravity 导出](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-updates/) · [DESIGN.md 开放格式](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-design-md/)

## 4. 业务逻辑与工程设计

### 场景与决策

- 固定场景 `BB-ORDER-750-001`。虚构云南基地，20 亩，05:40 虫情预警，750 kg A 级果订单，3 天交付。基准 25 人，每人每天 12 kg，三天采收产能 900 kg。采收产能与已通过质量门槛的可交付量分别计算。
- 关系数据覆盖基地、地块、批次、观测、订单、采收人员、资源、质量及合规规则。统一来源、单位、时间、有效期、版本和证据引用。关键数据缺失、过期或冲突时进入待核验。
- 比较 A 全面作物防护、B 分批放行与隔离、C 优先采收与隔离。先检查质量、交期、劳动力、合成采收安全间隔和数据有效性，再对可行方案评分。基准 B 领先须由数据和规则算出，推荐理由引用具体证据。
- What-if 调整交付剩余天数、人员、可用 A 级果和数据质量。每次保存生成新版本，重新计算并撤销旧审批的使用资格。1 天为 300 kg，15 人三天为 540 kg，两种情况都应明确升级处理。
- 六个决策视角聚合 14 个角色。默认展示决策摘要、分歧和证据，展开可查角色意见、来源、权限和否决依据。模型解释如接入，属于可选增强，规则、数字和整个 Demo 可在无模型联网时运行。

### 执行与授权

- **推荐实现**：沿用 React/Vite，添加薄 Node 仿真服务。现有 Zustand 承担视图状态，决策、审批、任务状态机与事件写入集中在服务中。首版以本地单进程和持久化场景仓库运行，支持现场断网；本地用原子提交并串行处理同一案例写入。线上预览若部署，选支持可靠持久化的运行环境，由相同服务处理请求。现有 SPA 配置与 `/api/demo/*` 的路由优先级在实施时验证。
- API 覆盖读取/更新场景、评估、审批、启动、暂停/恢复、故障注入、重置、事件与审计。服务验证演示身份、角色、方案及输入版本、有效期、硬约束和授权范围。运行中输入版本改变时，冻结仍依赖旧授权的任务，记录原因并要求重新评估。
- 所有执行入口统一校验。Demo 使用模拟人员、ERP 和设备适配器，服务端固定启用 Simulation，并拒绝真实执行调用。角色权限是演示授权模型。审批凭据记录审批人、时间、版本和范围。以执行和任务幂等键去重，有界重试后升级人工。
- Plan B 任务链：**T1 隔离复核 → T2 质检 → T3 重算采收分配 → T4 派发两组采收工单 → T5 预留合格果并准备订单 → T6 同步模拟外部系统 → T7 核验并生成执行指纹**。模拟时钟推进任务，前置条件、回执和状态转换决定能否进入下一步。暂停、刷新和重启后从已提交事件恢复，防止重复派单。
- **正常路径**：经理审批，自动运行，合格量满足 750 kg，状态为“模拟订单已准备”，指纹核验一致。**现场故障路径**：把 T2 回执设为 700 kg，记录短缺 50 kg，停止依赖任务，禁止预留并提示人工处理。另验模拟 ACK 超时、重试上限及人工升级。
- 指纹关联输入快照摘要、规则版本、方案、授权、任务回执与差异，作为完整性示例。审计区分别展示“任务完成”“执行已核验”“业务结果已验证”。经营账本单列收入风险和模拟贡献差额，避免把同一笔金额重复计入。PDF 导出根据现有能力和进度决定，JSON/CSV 为验收项。

## 5. 实施顺序与里程碑

工期是单条开发线的净工作日估算。P1 设计探索可以与 P2 领域实现并行，P0 后按实际基线和部署方式校正。

| 阶段 | 工作 | 完成条件 | 估算 |
| --- | --- | --- | --- |
| P0 基线审计 | 启动现有 Demo，记录 build/lint 和路由行为。核对已有蓝莓场景、14 角色、旧录屏入口、审批和模拟边界。产出复用及变更清单 | 明确开发基线、已知回归和可沿用组件 | 1 天 |
| P1 界面定方向 | Stitch 三页两套方案、关键交互状态，确定导航和 `DESIGN.md` | 关键数字、主要操作和阻断理由在投影及手机上可辨 | 1–2 天 |
| P2 做通经营决策 | 构建蓝莓数据、关系追溯、规则、三方案、六视角和 What-if，打通经营事件到审批入口 | B 由规则算出，缩短交期、减少人员和过期数据均触发对应阻断 | 2 天 |
| P3 做通授权执行 | 接入服务端审批、T1–T7、模拟适配器、故障、持久化与审计 | 正常与质检失败均可从 UI 跑通，支持刷新恢复、暂停、重复请求去重 | 2–3 天 |
| P4 完善全站与交付 | 落实视觉、双语、旧入口回归、证据导出、历史回放、E2E 和现场彩排 | 现场连续三次可复位演示，文档和验证结果齐备 | 2–3 天 |

**估算合计 8–11 个净工作日。** 如果先赶演示，P3 验收即形成可运行首版，P4 再完善视觉和交付。云预览开通、额外部署审批和现场素材制作另计。

## 6. 验收清单

| 验收项 | 可检查结果 |
| --- | --- |
| 首页与追溯 | 首页约 5 秒可识别企业经营定位。点 05:40 预警能追到具体批次、订单、人员与依据 |
| 决策与 What-if | A/B/C 指标可复算。基准 B 可行，交期 1 天、人员降至 15、数据过期、规则缺失和硬否决能产生对应阻断；旧审批随版本变化失效 |
| 授权与安全 | 直接请求执行服务也不能跳过经理审批、使用过期审批或重复派单。所有适配器回执明确为模拟 |
| 正常与故障 | 一次启动后自动跑完 T1–T7。700 kg 质检回执阻止库存预留，审计可定位 50 kg 差额。模拟 ACK 超时达到重试上限会升级 |
| 恢复与证据 | 执行途中暂停、刷新恢复、继续、复位；同一种子重放得到一致业务结果。导出的 JSON/CSV 含关联审批与回执 |
| 发布回归 | build 通过；旧路由可到达，主线无阻断性控制台错误；键盘焦点、手机布局和双语无截断；按 README 可本地启动 |
| 测试范围 | 单测覆盖约束、评分、授权失效、去重和偏差。E2E 覆盖正常、越权、What-if、质检故障、恢复及历史回放 |

### 90 秒现场操作

- **0–15 秒**：经营总览点开 05:40 虫情预警，展示 750 kg 订单及影响关系。
- **15–40 秒**：进决策室，对比 A/B/C，解释 B 的放行与隔离依据。将交期改为 1 天，展示阻断，再恢复为 3 天并重新评估。
- **40–70 秒**：经理点击 Approve & Run，4× 模拟速度展示质检、派工、预留和核验。
- **70–90 秒**：打开证据与收益，查看授权、回执及指纹。备有质检失败案例回放和可断网运行的本地版本。
