# Sentinel Demo 6.1 项目总览与交接

## 背景、目的与范围

Sentinel Demo 面向高价值作物的农场运营。以云南蓝莓为例，地块风险会影响合格批次、采收能力、订单交付与毛利。6.1 要让演示者从运营首页沿一条证据链说明发生了什么、系统怎样判断、谁授权、实际执行了什么，以及最终如何验证。6.1.0 是应用目标版本，V3.5 独立案例和 V3.6 展示材料各有自己的版本。

演示从持续运行的 Operations 开始，走 Dashboard → Risk → Prescription → Execution → Audit。蓝莓 Scenario 用于复现正常和异常路径。现场监测、出货与设备控制在当前版本以演示数据和回执表达。

## 业务与数据逻辑

1. 后台按时检查运营数据，出现异常时记录时间和依据。演示通过 Farm Ontology 的关系将地块、批次、订单和任务串起来。
2. 规则比较采收窗口、产能、合格量、数据新鲜度和预计贡献。人工授权绑定运行 ID、决策版本、方案和工单。
3. 执行处理质检及采收回执，按批次核算接收、隔离和预留。晚到证据可触发版本更新和放行拦截。审计保存授权、回执和证据指纹。
4. Ask Sentinel 根据页面和订单运行读取上下文。知识条目有来源、版本和审核状态。历史回放使用对应的记录与证据。

蓝莓基准为 **Grade A 750 kg、¥65/kg**，全额交付合同金额 **¥48,750**。基准质检通过 **780 kg**、接收 **760 kg**、预留 **750 kg**。一天交付名义产能 **300 kg**，至少缺 **450 kg**。质检确认 **700 kg** 时至少缺 **50 kg**，质检到达时点决定是规划阶段拦截还是后续放行拦截。区域价格变动触发复核，已签订单按合同价计算。
